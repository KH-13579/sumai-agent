# 見積AI デモ動画・ナレーション台本（約3分）

## 0:00–0:25　課題

画面：スマイエージェントのトップ画面。

ナレーション：

「間取りの検討では、希望が増えるほど建築費が見えにくくなります。一方、生成AIに金額を自由回答させると、回答の揺れや根拠不足が起こります。そこで見積AIは、AIに計算を推測させず、公的統計を基準にした計算ツールとして実装しました。」

## 0:25–1:10　標準ケース

操作：右側の見積AIに「100㎡、4,000万円、木造、2階、標準」を入力し、「計算する」を押す。

ナレーション：

「入力は延床面積、建物予算、構造、階数、仕様、追加設備です。100平方メートルの木造2階建て、標準仕様を計算します。結果は一点の金額ではなく、概算レンジと中心値で表示します。予算判定はレンジの上限を使うため、安全側の判断になります。」

## 1:10–1:55　予算超過ケース

操作：構造をRC造、仕様をプレミアムへ変更し、追加設備を3つ選択して再計算する。

ナレーション：

「次に条件を上げます。RC造、プレミアム仕様、太陽光、全館空調、ZEH級断熱を選ぶと、予算超過へ変わります。APIのJSONには、どの条件がいくら影響したかという内訳と、仕様変更、面積縮小、設備の将来設置などの削減候補も含まれます。」

## 1:55–2:35　技術上の特徴

画面：Swagger UIの `POST /api/estimate`、またはコードの構成表。

ナレーション：

「見積計算はLLMから分離しています。同じ入力には必ず同じ結果を返し、Ollamaや外部APIが停止していても動きます。入力値はスキーマで検証し、単価、係数、設備費、出典はJSONへ分離しました。将来データを更新するときも、計算コードを書き換えずに対応できます。」

## 2:35–3:00　限界と次の連携

画面：免責表示と全体フロー。

ナレーション：

「これは研究用モックの概算であり、土地費、地盤、外構、設計・申請、税などは未反映です。そのため契約や発注には使わず、専門家の正式見積が必要であることを明示しています。今後は間取りAIの面積を自動入力し、予算超過時に間取りを修正する自律ループへ接続します。」
